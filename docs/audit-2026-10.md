## 3. Sound findings

- `src/lib/sound.ts` has three synthesised cues (open, close, tick) and an on/off flag. There's **no volume control**, **no ambience channel**, **no asset pipeline**, and only a binary toggle in `Header.tsx`.
- **No licensed audio assets exist.** Nothing can be "reused" because nothing was supplied.
- **Plan:** an engine with master volume, a cue bus and an ambience bus, and a manifest of file slots (`public/audio/*`) that load lazily once supplied, with format fallback. Until then, the existing synthesised cues are kept but refined (softer, with a short procedural room reverb). Procedural ambience is opt-in and clearly labelled as a stand-in. The control becomes a popover with on/off, ambience and volume, all keyboard-accessible.

## 5. Technical and performance findings

- First load is 235 KB JS + 11 KB CSS (gzip), measured in the previous pass. That's acceptable; the WebGL loop already pauses when off screen, hidden or covered.
- Console clean; axe 0 violations (previous pass).
- `STATIC_EXPORT` / single-file build (`scripts/build-single-html.mjs`) **can't coexist with server routes** (`output: 'export'` forbids POST route handlers). See the resolution in §6.
- No unit tests exist. Validation and rate-limit logic will get tests.

## 6. Conflicts and ambiguities

| Topic | Master brief | This brief | Resolution |
|---|---|---|---|
| Sales model | Full e-commerce (cart, checkout, payments) | "If the current demo is enquiry-led, make enquiries fully functional instead of a fake checkout" | **Enquiry-led for now.** No payment provider is approved. Cart, checkout and payments remain `Not started`, never simulated. **Business decision needed:** direct online sales or enquiry-led? |
| Persistence | Secure persistent enquiry records | Store or forward per the approved architecture | No database exists. Implemented a **storage adapter**: Supabase REST (when keys are set; SQL migration provided) **or** a local JSON-lines file (genuinely works on a Node server, but not durable on serverless). With neither configured, the endpoint returns 503 and the UI says so honestly, offering email instead. |
| Admin | Role-based admin dashboard | Don't build an insecure public admin | Minimal enquiry review behind HTTP Basic auth (proxy + per-handler checks), disabled entirely unless credentials are set; `noindex`. A full multi-role admin needs an auth provider decision. |
| Single-file HTML | Previously requested | Multi-page site with a backend | A multi-page site with server endpoints can't be one offline HTML file. The single-file build is **retired**; a hosted preview is the right review format. |
| "Large site" vs "no fake products" | Scale and depth | Keep 2–3 real samples | Depth comes from distinct page types and editorial treatments of the same authentic photos. No invented products, collections or counts. |
